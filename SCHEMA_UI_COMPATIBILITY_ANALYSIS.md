# Database Schema vs UI Data Compatibility Analysis

## Books Table Schema

```sql
CREATE TABLE books (
    id TEXT PRIMARY KEY,
    title TEXT NOT NULL,
    author TEXT NOT NULL,
    isbn TEXT,
    genre TEXT,
    publisher TEXT,
    publication_year INTEGER,
    total_copies INTEGER DEFAULT 1 NOT NULL,
    available_copies INTEGER DEFAULT 1 NOT NULL,
    shelf_location TEXT,
    cover_image_url TEXT,
    description TEXT,
    status TEXT DEFAULT 'available',
    category_id TEXT,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now')),
    condition TEXT,
    book_code TEXT UNIQUE,
    acquisition_year INTEGER DEFAULT 2024,
    legacy_book_id INTEGER UNIQUE,
    legacy_isbn TEXT,
    synced INTEGER DEFAULT 0,
    sync_version INTEGER DEFAULT 1,
    deleted INTEGER DEFAULT 0
);
```

## UI Form Data (from SimpleBookForm.tsx)

The UI sends the following data structure (lines 107-115):

```javascript
{
    ...formData,  // spreading form fields
    publication_year: parsed_integer,
    total_copies: formData.number_of_copies,
    available_copies: book ? book.available_copies : formData.number_of_copies,
    generated_codes: generatedCodes,      // Array of strings like ["HCC/300/22", "HCC/301/22"]
    start_number: nextLegacyId           // The starting legacy book ID
}
```

Where `formData` contains:
```javascript
{
    title: string,
    author: string,
    publication_year: number,
    category_id: string,
    shelf_location: string,
    number_of_copies: number,
    book_code: string,           // e.g., "HCC/300/22"
    prefix: string,             // e.g., "HCC"
    acquisition_year: number    // e.g., 2025
}
```

## Book Copies Table Schema

```sql
CREATE TABLE book_copies (
    id BIGINT PRIMARY KEY,
    book_id TEXT,                    -- Foreign key to books table
    isbn TEXT NOT NULL,
    title TEXT NOT NULL,
    author TEXT NOT NULL,
    publisher TEXT,
    publication_year INTEGER,
    copy_identifier TEXT NOT NULL UNIQUE,
    acquisition_date TEXT DEFAULT (date('now')),
    condition TEXT,
    status TEXT NOT NULL,
    location TEXT,
    department_id INTEGER,
    current_borrower_id TEXT,
    borrowed_at TEXT,
    due_date TEXT,
    legacy_book_id INTEGER,          -- Should contain the NUMBER from PREFIX/NUMBER/YEAR
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now')),
    synced INTEGER DEFAULT 0,
    sync_version INTEGER DEFAULT 1,
    deleted INTEGER DEFAULT 0
);
```

## Compatibility Analysis

### ✅ Fields that match correctly:
- `title` → `title`
- `author` → `author`
- `publication_year` → `publication_year`
- `category_id` → `category_id`
- `shelf_location` → `shelf_location`
- `book_code` → `book_code`
- `acquisition_year` → `acquisition_year`
- `total_copies` → `total_copies`
- `available_copies` → `available_copies`

### ⚠️ Fields that need mapping in backend:
1. **generated_codes** → This is an array that needs to be used to create individual book_copies records
2. **start_number** → Should be used as `legacy_book_id` for the main book record
3. **prefix** → Not stored in database, only used for code generation
4. **number_of_copies** → Maps to `total_copies`

### 🔴 Missing fields that backend must provide:
For books table:
- `id` (UUID) - Generated by backend
- `isbn` - Can be NULL
- `genre` - Can be NULL
- `publisher` - Can be NULL
- `cover_image_url` - Can be NULL
- `description` - Can be NULL
- `status` - Default 'available'
- `condition` - Can be NULL
- `legacy_isbn` - Can be NULL
- `created_at`, `updated_at` - Auto-generated
- `synced`, `sync_version`, `deleted` - Default values

For book_copies table (per copy):
- `id` (BIGINT) - Generated by backend
- `book_id` - Must link to parent book
- `isbn` - Backend sets as "UNKNOWN" or similar
- `copy_identifier` - From generated_codes array
- `condition` - Default 'good'
- `status` - Default 'available'
- `legacy_book_id` - Extract from copy identifier (e.g., 300 from "HCC/300/22")

## Current Backend Implementation Issues

Based on the code review, the backend correctly:
1. ✅ Receives the data structure from UI
2. ✅ Maps fields to book record
3. ✅ Extracts legacy_book_id from copy identifiers
4. ✅ Creates book copies with proper relationships

## Recommendations

1. The schema and UI data are generally compatible
2. The backend is correctly handling the mapping between UI fields and database fields
3. The main issue was in the copy creation logic (which has been fixed)
4. Consider adding validation for:
   - Ensuring generated_codes array is not empty
   - Validating copy identifier format (PREFIX/NUMBER/YEAR)
   - Checking for duplicate copy identifiers before insertion
